# Agent Guide for This Repository

## Scope

This repository is a Hugo-based personal website. It is not a generic web app. Most changes should stay within Hugo configuration, templates, content, and CSS overrides.

The site currently supports:

- bilingual content: Chinese (`zh`) and English (`en`)
- academic-style homepage
- about page
- publications section
- technical blog section
- essays section
- search page
- mobile long-image export for posts/pages

This document is intended for other agents that need to modify or extend the site without first reverse-engineering the repo.

---

## Core Stack

### Framework

- **Hugo extended**
  - minimum expected version: `0.146.0`
  - configured in [makefile](../makefile) and required by the PaperMod theme

### Theme

- **PaperMod**
  - configured in [hugo.toml](../hugo.toml)
  - located in `themes/PaperMod`
  - used as a base theme, with local template overrides in `layouts/`

### Styling

- Hugo/PaperMod base CSS
- local override CSS in:
  - [assets/css/extended/terminal-home.css](../assets/css/extended/terminal-home.css)
  - [static/export-mobile.css](../static/export-mobile.css) for mobile image export

### Content format

- Markdown content under `content/`
- TOML front matter is used throughout

### Search

- Hugo JSON index output
- PaperMod fastsearch script with local customization

### Export tooling

The repo includes a content-to-image export path for mobile reading cards:

- `wkhtmltopdf`
- `pdftoppm` from `poppler-utils`
- `mogrify` from `imagemagick`
- `chromium-browser` remains used for raw screenshot export

## Content Authoring Rules

### New technical blog post

Use:

```bash
make new SECTION="technical-blog" TITLE="My Post Title"
```

This:

- validates the section
- generates a slug from `TITLE`
- uses the `technical-blog` archetype

### New essay

Use:

```bash
make new SECTION="essays" TITLE="My Essay Title"
```

### New publication

Use:

```bash
make new SECTION="publications" TITLE="Paper Title"
```

### Front matter expectations

For blog-like content, common fields are:

- `title`
- `date`
- `draft`
- `description`
- `readingTimeText`
- `tags`
- `categories`

The site already supports manual `readingTimeText` via a local `post_meta` partial override.

### About page as data source

The homepage reads education and internship data from:

- [content/about.md](../content/about.md)
- [content/about.en.md](../content/about.en.md)

Do not duplicate education/internship data in multiple places. Update the `about` front matter arrays instead.

## Homepage Architecture

Homepage rendering is custom, not stock PaperMod.

Main file:

- [layouts/index.html](../layouts/index.html)

Current structure:

- left sidebar:
  - profile image
  - name
  - affiliation
  - short bio
  - contacts
- right content:
  - intro/about
  - news
  - publications
  - education
  - internships
  - honors

Data sources:

- homepage text and contacts: `hugo.toml`
- education and internships: `content/about*.md`
- publications: `content/publications/`

When extending homepage sections, prefer keeping the data source singular.

## Bilingual Behavior

The site is multilingual.

Primary configuration:

- [hugo.toml](../hugo.toml)

Languages:

- `zh`
- `en`

Rules:

- Chinese is default language
- English lives under `/en/`
- menus are defined separately per language
- content files may use:
  - paired files such as `about.md` and `about.en.md`
  - language-specific `_index` files for sections

If a change is user-facing, check whether it should exist in both languages.

## Search Implementation

Search is not default browser search. It depends on:

- Hugo home output including JSON
- custom search page layout
- local fastsearch behavior

Relevant files:

- [layouts/search.html](../layouts/search.html)
- `themes/PaperMod/assets/js/fastsearch.js`
- `content/search.md`
- `content/search.en.md`

Header search UI is implemented in:

- [layouts/_partials/header.html](../layouts/_partials/header.html)

If search behavior breaks, inspect both the header form action and the JSON search index path.

## Styling Model

There are two distinct style layers.

### 1. Normal site browsing

Primary override file:

- [assets/css/extended/terminal-home.css](../assets/css/extended/terminal-home.css)

This file controls:

- custom homepage layout
- academic section lists
- catalog/list pages
- header layout
- nav search box
- responsive spacing

### 2. Mobile export mode

Dedicated export stylesheet:

- [static/export-mobile.css](../static/export-mobile.css)

This is intentionally separate from the normal browsing CSS.

It controls:

- dark export theme
- hiding nav/search/footer UI
- mobile typography
- code wrapping
- page-size behavior for export

Do not mix export-only rules into the normal browsing stylesheet unless necessary.

## Export Pipeline

### Raw screenshot export

Command:

```bash
make export-mobile-image PAGE="/technical-blog/cute-starter-1/"
```

Uses:

- `hugo server`
- `chromium-browser --headless`

This is a screenshot path, not a paginated reading-card path.

### Paginated mobile card export

Command:

```bash
make export-mobile-cards PAGE="/technical-blog/cute-starter-1/"
```

Uses:

1. local `hugo server`
2. `wkhtmltopdf` to render a fixed-size mobile PDF
3. `pdftoppm` to split PDF pages into PNGs
4. `mogrify -trim +repage` to remove white borders if available

Default output directory:

- `exports/<page-slug>/`

Example:

```bash
make export-mobile-cards PAGE="/essays/at-the-end-of-june/"
```

outputs to:

- `exports/at-the-end-of-june/`

### Export dependencies

Install via:

```bash
make install-mobile-export-deps
```

This installs:

- `chromium-browser`
- `fonts-noto-cjk`
- `poppler-utils`
- `wkhtmltopdf`
- `imagemagick`

Notes:

- `chromium-browser` on Ubuntu may be snap-based and unreliable in restricted environments
- the current mobile card pipeline uses `wkhtmltopdf` instead of Chromium for pagination

## Known Design Constraints

1. This is a content site, not a client-heavy app.
   - avoid introducing unnecessary JS frameworks

2. The theme is PaperMod-based.
   - use local overrides first
   - avoid deep theme forks unless required

3. The homepage is custom and data-driven.
   - preserve current ownership boundaries for data

4. Export styling is isolated.
   - keep export concerns in `static/export-mobile.css`

5. Content and generated output should stay separate.
   - do not edit `public/` as source

## Safe Extension Points

Preferred extension points:

- `hugo.toml` for menus, params, homepage metadata
- `layouts/` for rendering changes
- `assets/css/extended/terminal-home.css` for normal UI styling
- `static/export-mobile.css` for export-only appearance
- `archetypes/` for content generation defaults
- `content/` for source content and language variants

Use theme edits only when all override-based options are exhausted.

```bash
make preview
```

```bash
make setup-hugo
```

```bash
make new SECTION="technical-blog" TITLE="My Topic"
```



## Guidance for Further Development

### When adding a new section

You need to update, at minimum:

1. `content/<section>/`
2. section `_index.md` and `_index.en.md`
3. `hugo.toml` menus if it should appear in navigation
4. `layouts/<section>/list.html` if custom list rendering is needed
5. `archetypes/<section>.md` if new content creation should be standardized

### When changing the homepage

Check:

1. [layouts/index.html](../layouts/index.html)
2. [assets/css/extended/terminal-home.css](../assets/css/extended/terminal-home.css)
3. `hugo.toml`
4. `content/about*.md` if education/internship data is involved

### When changing blog post rendering

Check:

1. PaperMod page defaults
2. local partial overrides such as:
   - [layouts/_partials/post_meta.html](../layouts/_partials/post_meta.html)
   - [layouts/_partials/extend_head.html](../layouts/_partials/extend_head.html)
3. CSS in `assets/css/extended/terminal-home.css`

### When changing export behavior

Check:

1. [makefile](../makefile)
2. [static/export-mobile.css](../static/export-mobile.css)
3. whether the issue is:
   - HTML/CSS rendering
   - PDF page sizing
   - PDF to PNG conversion
   - post-processing trim behavior

Do not assume the bug is in only one layer.

## Failure Modes to Watch

- invalid TOML front matter in any content file can break `hugo new`
- menu links can accidentally resolve to absolute production URLs if templates use the wrong URL helper
- export output can appear correct in browser preview but fail in PDF/image export due to renderer differences
- Chromium-based export and wkhtmltopdf-based export behave differently; treat them as separate backends
- `.post-title` and `.post-content h1` are different targets; do not treat them as the same heading

---

## Minimal Rule Set for Future Agents

1. Read the actual local overrides before touching the theme.
2. Treat `hugo.toml`, `layouts/`, and `assets/css/extended/terminal-home.css` as primary sources of truth.
3. Keep bilingual changes symmetric unless the feature is intentionally language-specific.
4. Keep export-specific logic isolated from normal browsing logic.
5. Do not edit generated output in `public/`.
6. Validate assumptions against current files, not against generic Hugo/PaperMod defaults.
